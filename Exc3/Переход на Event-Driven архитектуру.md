Проблемы текущей архитектуры:
    1. Запросы на получение данных о продуктах и тарифах долго обрабатываются, поскольку ins-product-aggregator выполняет синхронные запросы ко всем страховым компаниям;
    2. Core-app с задержкой получает данные и есть риск того, что они будут неактуальны;

Решение: переход на Event-Streaming:

    1. ins-product-aggregator в фоновом режиме, с определенной периодичностью отправляет запросы ко всем страховым компаниям, агрегирует их и публикует событие [InsProductDataUpdated] в Kafka.
    2. core-app подписывается на [InsProductDataUpdated], сохраняет и использует полученные данные для дальнейшего отображения по запросу от клиентов;
    3. ins-comp-settlement подписывается на [InsProductDataUpdated] и использует последний полученный апдейт в процессе взаиморасчетов;
    4. core-app публикует в Kafka событие [NewInsuranceCreated], на которое подписан сервис ins-comp-settlement - тот сохраняет полученные данные в БД и использует их при ночном расчете.

Таким образом, мы избавляемся от привязки получения сервисами core-app и ins-comp-settlement данных через REST-запросы и уменьшаем время ответа ins-product-aggregator

Для применения паттерна Transactional Outbox, необходимо сделать следующее:
    1. Создать отдельную БД для сервиса ins-product-aggregator, в которую будут записываться данные по продуктам\тарифам от страховых компаний (убрать эту функцию у core-db);
    2. Настроить outbox-таблицу для этой БД + Debezium для считывания обновлений с outbox таблицы и публикации событий в топик [InsProductDataUpdated] 
    3. Перенести из ins-comp-settlement-db в core-db функцию хранения данных об оформленных страховках
    4. Настроить outbox-таблицу для core-db + Debezium для считывания обновлений и публикации событий в топик [NewInsuranceCreated]

Вывод: сделать можно, но с изменением архитектуры хранения данных, что может быть достаточно трудоемко. С учетом того, что обновление данных по тарифам происходит с установленным лагом (например, 5 минут), вероятность наличия проблемы двойной записи *крайне мала*.
