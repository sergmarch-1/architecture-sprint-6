Проектирование osago-aggregator и интеграции с core-app:

    1. Отдельная БД для нового сервиса необходима, чтобы сервис работал автономно и сохранял\апдейтил состояния заявок без обращения к core-app;
    2. Взаимодействие между osago-aggregator и core-app через Kafka (+debezium для согласованности данных)
    3. Доработка API core-app для веб-приложения - настройка возможности подключения через WebSocket при оформлении ОСАГО
    4. Паттерны отказоустойчивости:
        - Rate Limiting - для ограничения входящих запросов от клиентов;
        - Circuit Breaker при обращении к страховым компаниям, чтобы не отправлять запросы в случае, если их API недоступны
        - Retry при получении ошибок 500 или 504 от АПИ страховых компаний
        - Timeout - для ограничения времени ожидания ответа по ОСАГО (60 секунд)
    5. При наличии нескольких экземпляров сервисов, необходимо:
        - настроить Kafka Consumer Group - топик osago-requests должен иметь столько партиций, сколько экземпляров osago-aggregator запущено в данный момент. Аналогично для core-app и osago-offers.
        - Использовать механизм sticky sessions, чтобы избежать дублирования сообщений от core-app во время Websocket соединения с приложением
